# 聯絡收件部署備註

這份功能包含新資料表，不是只更新前端。先備份、確認目標環境與待執行計畫，再由有權限的部署人員套用 `Client.0008_contact_inbox`；不要在不確定的資料庫執行。開發代理僅在本機 `127.0.0.1:3308/test_snowland` 套用，未修改正式庫。

## 開通

1. 更新前後端並確認 migration 後，登入「營運管理 → 聯絡收件」。
2. 總部管理員展開「表單與通知信設定」，開啟官網表單。預設為關閉，避免新版未設定就公開收件。
3. 需要通知時再開啟寄信並填收件信箱。SMTP 使用部署環境既有 `EMAIL_*` 與 `DEFAULT_FROM_EMAIL`；信件只提示有新留言，不包含訪客原文或聯絡資料。寄信失敗不會撤銷已收留言。

集中收件僅總部範圍、具 `contact_inbox` 權限的人員可讀寫，行政小幫手預設具有此權限；校區角色、教練與只有官網編輯權限者不開放。收件開關與通知目的信箱僅總部管理員可修改。

## 反向代理與防濫用

`SNOWLAND_CONTACT_RATE` 預設為每個網站、每個訪客IP每分鐘5次（`5/min`）。資料格式錯誤或重複請求也計次，429會提示稍後重試。

預設忽略外部傳來的 `X-Forwarded-For`，避免任意偽造IP繞過限制。若服務在ngrok／Nginx等代理後方，部署人員必須核對實際連到Django的代理來源IP及轉送鏈，再設定 `SNOWLAND_CONTACT_TRUSTED_PROXY_IPS`（以逗號分隔的確切IP，不支援CIDR）。只在直接連線來源屬於可信代理時，從右向左取第一個非可信IP作為訪客。代理須正確附加真實來源，不能原樣透傳任意訪客標頭。

未設定可信代理時，同一代理後的訪客可能共用限流名額。多worker／多主機正式部署應使用共用cache，否則各程序限流計數互不共用。正式流量及外部寄信送達仍須部署環境驗收，本機測試不代表已開通。

## 操作與邊界

- 訪客必填姓名、Email、主旨、訊息，電話選填。成功回傳收件編號；失敗保留輸入。同一送出編號及相同內容不會重複建立留言。
- 行政可查看原文、標記未處理／處理中／已處理及寫內部備註，不可改寫訪客原文。此頁不提供直接回信或刪除留言。
- 通知發送失敗可手動重試；SMTP逾時可能已被郵件伺服器接收，人工重試前應先核對，以免重複通知。沒有自動無限重寄。
- 訪客資料保存在獨立私密資料表，不會寫入可公開查詢的CMS、會員資料或訂單。
