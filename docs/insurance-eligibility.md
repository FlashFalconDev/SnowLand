# 不符投保資格

在 Django Admin 的「模組設定」選擇該租戶啟用中的 `booking` 模組。在既有 `settings` JSON 補入以下鍵，保留原有設定。兩個鍵都只接受 JSON 布林值。缺值、錯型、停用設定列或模組均視為 `false`。

| 設定鍵 | 預設值 | 用途 |
| --- | --- | --- |
| `insurance_eligibility_enabled` | `false` | 開放新增「不符投保資格」標記。 |
| `insurance_eligibility_allow_admin` | `false` | 開放具 `insurance_records` 權限的行政小幫手、校區主管、校區校長及舊版行政帳號操作。 |

有 `insurance_records` 權限的保險人員及總部管理員可在獲授權的租戶與校區操作。兼任者使用該租戶的有效職位及合併後權限。從「尚未投保」、「對資料中」或「處理中」可標記不符。「已投保完成」須先核對原投保紀錄。復原一律回「對資料中」。關閉新增開關後，原標記仍可查看、篩選及由有權限的人復原。

不符時，列表與月曆各自顯示標記和計數。標記會保留已填保費，並禁止新增正保費與寄送保險資料提醒。聲明書提醒沿用原規則。需重核的改期／換課會保留原判定與原保費並將現行狀態切回「對資料中」。會員只會看到「待行政確認」。發布時先以開關關閉的設定部署，驗證後再由租戶開啟。
