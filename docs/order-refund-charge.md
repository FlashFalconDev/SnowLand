# 訂單修改差額補款與退款

## 啟用與權限

1. 在 Django Admin 的「模組設定」選擇該租戶已啟用的 `booking`，在現有「模組特定設定」JSON 加入 `"order_refund_charge_enabled": true`，保留其他鍵。停用時把該鍵改成 `false`。缺值、非布林值、模組或該租戶的設定列停用時，功能預設關閉。
2. 在後台「員工與權限」的職位設定勾選「對帳與差額」`order_payments`，再依職務勾選下表的權限並指派該職位。總部預設全權與舊 `orders` 都需要個別指派這些新權限。行政小幫手預設沒有審核權。
3. 由「對帳與差額」選差額進度，開啟訂單，再用橫幅進入「差額回報與核對」。可從「自動通知」進入待補款或待審核的清單。測試單可用「顯示測試訂單」查找。

| 權限碼 | 操作 |
| --- | --- |
| `order_charge_operate` | 取得補款連結、登記已通知、核對外部補款 |
| `order_amendment_refund_request` | 提出整筆修改差額退款申請 |
| `order_amendment_refund_review` | 核准、駁回、登記實際完成的外部退款 |

## 作業規則

- 補款使用修改時保存的原幣、金額及匯款帳戶。會員從自己的訂單回報末五碼。訪客連結限該租戶、訂單與差額，30 天到期。差額停止收款、結清或功能停用後，訪客頁無法再取得匯款指示。
- 退款申請須填完整差額及原因，同一筆差額不得分批退。退款上限為原實收加減同幣別的已結清差額。舊台幣單在缺少實收快照及其他帳務憑據時，以第一筆已付款修改前的價格作為基準。外幣正式單須有原幣實收快照。
- 核准後照外部銀行或金流流程退款，再登記外部交易參考及核對依據。已核准的退款帳戶暫停變更。若確認尚未退款，可駁回後補資料或重新申請。申請中或已核准時，須先結束差額退款再改單或申請整單取消。整單取消使用既有「取消與退款」。
- 關閉功能後既有補款回報、核對與未進工作流的舊退款可依原流程處理。已進工作流的差額退款保留歷史，重新啟用後才能繼續。
- 測試單使用合成交易資料，可用未付款的原單模擬補退。訪客連結、原付款與正式帳務不受測試操作影響。有待處理測試差額或工作流紀錄的訂單須保留測試標記。

本功能使用人工核對與既有帳務。請在系統外完成實際收退款。正式發布、啟用或修改正式資料須另依 [發布與回退手冊](backend-eb-release-rollback.md) 走兩步確認。本次改動無 migration。
